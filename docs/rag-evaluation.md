## 三个检索错误

- **天书漏召回**。「家里催我结婚」「对象该比我大还是比我小」和卡片的「父母催婚」「对象年龄差」只命中「结婚」一个双字片段。这个例子需要识别整句的意图和表达变体。
- **曲曲错候选**。「第一次约会发生餐馆食物过敏」的「第一次约会」恰好拆成四个重叠词，达到了当前阈值，返回 AA 后续约的案例。与实际问题「食物过敏」和「餐厅处理」无关。
- **郭延娇错候选**。「婆婆跌倒和养老保险理赔」一题只共享「最近」「婆婆」「具体」，仍在补查后返回婆媳相处片段。人物称呼和时间词无法说明案例可以回答保险问题。

这三处都是检索阶段的结果，不代表用户最终会看到一段错片。已知题目可用于排查和回归，调整后应另外用新的问法测主题匹配和拒绝。每位只测了两道正题，正题目标是开发和上线片段，这组测试只比较案例覆盖和相关性，不估计新来访场景的整体成功率。

## 复跑

从仓库根目录运行。首先用固定题目对比三组，检查每位的正例、近似无匹配、主播归属和时码。候选通过后，再看回复是否引用同一来源和具体动作。脚本从本地 Git 标签只读提取两版 SQLite，也可用 `--baseline-db` 和 `--current-db` 指定已解包数据库。需要 Python 3.13 和支持 FTS5 的 SQLite。

```sh
python3 evals/rag-heldout-eval.py --out /tmp/yuelao-rag-heldout-results.json
```

## 真实生成的结果

八位各取一道新增场景，每题实际生成三次，各用一个临时 Codex 会话。三组的模型、用户问题和共同提示词固定，原片锚点从提示词删除，只替换无案例、v0.2.8 候选或 v0.2.9 候选。模型输出候选 ID，程序只允许给出索引中有的链接。新库组在七位的答复里引用了预先指定的原片与秒数，另两组都是 0/8。天书在没拿到候选时给了追问，没有编链接。现在可以说七位更容易给出证据，语气和咨询质量仍需要独立盲评或试聊反馈。 [24 条实际生成](../evals/rag-response-results.json)

首轮生成把梵公子本人观点片误称为第三方。v0.3.0 针对两个片源写明不同出处，并在生成对照里把观点片链接标成「看观点片段」。已知误召回的两道题也做了复测，曲曲和郭律在生成阶段都没有推荐跑偏的候选。检索候选本身仍会误召回。针对已知错误的复跑属于回归验证。 [引片复测](../evals/rag-response-retargeted.json)

## 四题匹配怎样验证

维护四道场景题和每题四句回应、校对题目与选项的主播映射、对八个唯一获胜组合跑测试，再验证同分、跳题、全空、点名和旧版入口。每位在题库里有两次出现机会。匹配题检验的是选择逻辑，原片题检验的是能否给出相似证据。

```sh
python3 -m pip install -r server/requirements.txt pytest
PYTHONPATH=server python3 -m pytest -q evals/test_style_matching.py
```
