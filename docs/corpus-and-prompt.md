## 一段视频怎么变成知识

1. **登记原片。** 保存平台 ID、发布账号、链接、时长和来源类型。同一场连麦的完整版和切片合到同一事件，优先用来源明确、问答连续的版本。
2. **转写并定位。** 有公开可用字幕就记录字幕来源，否则从可访问的原片本机转写，保存每句的起止秒数。核听时分辨主播、来访者和转述内容。遇到听不清、答复缺失或身份不明的地方，记下缺口。
3. **按对话动作做短卡。** 切在「来访者说了什么 → 主播问了什么或怎么回应」可以对得上的地方。分别写情境和动作，补约 5–9 个能区分问题的标签，加同一原片的时码、出处和核验状态。只保留理解动作所需的事实。一个视频有两个独立的有效动作时可以有两张卡。
4. **建索引。** 全量 Script 留在研究库。聊天库用 SQLite FTS5 为短卡和窗口建立中文词项索引。部署快照保留短卡和限于已整理词表的无序词项。返回给用户的链接和时码取自同一张短卡。

**郭律实作。** 本人发布的 206.24 秒视频已下载解码，本机 Whisper 转写出 61 段，选 **02:39–02:58** 制成一张卡。情境是来访者不想生育，想在相亲刚认识时确认对方的计划。动作是把话术问题落到早期直接确认「对方是否想要孩子」。卡片保留沟通动作，省去来访者的病史和身份细节。音频和说话人仍待人工复核。 [带时码原片](https://www.bilibili.com/video/BV13Zxe6QEv6/?t=159)

## Jackychen 的 Skill 怎么接这张卡

Jackychen 的原版入口在 `SKILL.md`。鳌烨根据来访需求走不同的条件采集与分析分支。天书先区分「定位自己」和「看具体对象」，按需读长短择或资产口径等参考页。这里沿用这种**先定这轮任务、再按需加载材料**的组织方式，把接话规则写在 Skill 和主播参考页。动态案例由工具按本轮情境检索。 [Jackychen 鳌烨 Skill](https://github.com/Jackychen-12/yuelao-aoye-skill/blob/eea85ab67596113c766014c58ce5c84932ef8919/SKILL.md) · [Jackychen 天书 Skill](https://github.com/Jackychen-12/tianshu-dingwei-skill/blob/17a1cd73afcaabde558c761486a1b0ac9610b5e2/SKILL.md)

```text
固定指令    当前聊法、本轮是先听、追问还是给建议
对话上下文  用户已确认的事实、刚补充的事实和当前目标
按需检索    search_relationship_cases(question, host, limit=2)
工具结果    情境、接话动作、来源、起止秒数、核验状态
本轮回复    先接用户这件事。需要举例时用至多一张匹配卡。
```

比如用户说「我不想要孩子，他说顺其自然」时，郭律聊法先帮用户问清双方计划。用户补充说对方明确想要孩子，下一句据此更新判断。用户要看相似原片时，才以 `host=guolu` 查询这两条事实。MCP 把结果作为本轮工具消息放进模型上下文，模型可给卡里的 02:39 链接。查无合适结果时继续根据已知事实接话。试验脚本里有同一思路的另一种做法，先查 SQLite，再把 `retrieved_cases` 放进这次生成输入。 [插件指令](../plugin/skills/yuelao-case-chat/SKILL.md) · [MCP 工具](../server/yuelao_mvp/case_mcp.py)

## 评估怎么做

项目已对照过固定版本的 Jackychen 原版、压缩指令、相同压缩指令加短卡三组。三组使用相同的虚构输入。加短卡组在两次请求视频时找到了回京取舍和邀约投入的对应原片。新一轮要按整场连麦留出案例，给原版和两种改造版同一轮能知道的事实。分开检查第一句追问是否抓到关键分歧、收到补充是否改判、检索前两张是否含正确原片、链接是否指到对应动作，以及无匹配时是否拒绝乱引。留出的原主播答复用于独立核对。第一批可每位先选 12 场独立连麦，8 场整理短卡，4 场整场留出。按开场、补事实、改判和建议的动作覆盖选片。单场只卡一个动作时就出一张。这个数量是试采目标，后续按覆盖和留出结果加片。
